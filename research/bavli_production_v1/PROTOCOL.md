# Production protocol 1

Schema is `2.0.0-production`. Interactive agents read exact pinned source and save proposals; no API or semantic heuristics are called by the runner. Agent/model identities are recorded only as observed (unknown model is null). All annotations remain AI provisional, unreviewed, and ineligible for ML. No extraction coverage implies independent review.

Read complete relevant continuations. Preserve anonymous alternatives, uncertainty, conditions, local status, transmitter/holder distinctions, and repeat occurrences. Literal evidence uses Python Unicode code-point half-open offsets in original strings, including markup. Source paraphrase and editorial inference must be distinguished. `content` keys are typed by layer in schema.json. Links reference accepted or same-proposal record IDs. New revisions use new IDs and explicit `supersedes`; original proposals remain immutable. Changed records cannot inherit qualification.

Required passes are structure, utterances, claims, attributions, questions, positions, edges, and reconciliation. Coverage is per original source segment per layer. Completed structure coverage requires an exact nonoverlapping partition of every character by primary structure evidence. Nested structure may overlap but is not primary ownership. Empty segments are inventoried and require explicit not-applicable rationale. Completed zero-record passes need a rationale; reconciliation requires an actual source-based omission pass. Review is separate and not implemented as automatic agreement. Delivery remains incomplete until independent-review artifacts and policy gates are supplied.

Jobs are isolated external directories. `OWNER.json` holds a tractate-local epoch and owner. Every mutation holds an exclusive OS advisory lock. Only the coordinator/lane lead may issue the `handoff` command; same-lane changes are delegated, cross-lane changes require coordinator authority. The runner enforces expected owner and epoch, not organizational identity authentication. Global assignment revisions do not affect these epochs. Proposals bind source, schema, and protocol hashes. Run-contract/production commit binding lives in the coordinator's immutable run contract; agents must verify that before dispatch.

Submitted proposal bytes are content-addressed and never overwritten, including rejected attempts. Accepted checkpoint chains are immutable, content-addressed JSON. Promotion writes immutable snapshot, then atomically replaces CURRENT.json. A crash before pointer replacement leaves the previous checkpoint valid. Resume reruns the same submit; identical bytes are idempotent. Replay reads the accepted chain only, rechecks original source bytes, validates every proposal and reproduces the complete final snapshot hash. Orphan files never count as accepted work. Owner lock is released by the OS on process exit.

Legacy migration preserves exact JSONL file bytes, record IDs and original records; source segment IDs remain identical to v1. Legacy semantic tables are explicitly mapped as `unmapped` to production semantics, because selected/coarse v1 records do not establish atomic claims or completed layers. Compatibility export returns the original bytes. Loss report explains that new schema-2 interval structure and atomic semantic records have no fabricated v1 representation. Migration does not automatically count legacy semantics as completed production passes. Reannotation may link original IDs in its content; originals stay recoverable.

No full source files or full inventories belong in Git. Keep external job directories and source packages outside the checkout. Publish bounded proposal evidence and hashed receipts where authorized. Preserve Wikisource/Sefaria edition metadata and CC-BY-SA attribution without inventing a numeric license version.
